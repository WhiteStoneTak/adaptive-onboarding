# Product archetypes: starting hypotheses, not universal flows

A product can match multiple archetypes. Decide based on the actual job, dependencies, acquisition intent, economics, and risk.

| Archetype | First meaningful value candidate | Potential must-haves | Competing flow hypotheses | Important guardrail |
|---|---|---|---|---|
| Learning / tutoring | Demonstrates new understanding on a question | Safe content, learner level, age-related protections | Sample exercise first vs account for saved progress | Correct learning, meaningful return |
| Consumer utility | Completes a real task | Camera/input, privacy, possibly permission | Live task first vs honest example preview | Result quality, user control |
| Generative AI | Useful requested output | Input data, compute cost, consent/IP rules | Guided prompt vs direct creation | Useful output, costs, latency |
| Social / network | Finds relevant people or interactions | Trust, moderation, network density, identity | Interest-first vs invitation-first | Safety, spam, real connections |
| Marketplace | Finds or completes transaction | Identity, supply, location, payment | Browse first vs transaction-first | Fraud, delivery reliability |
| Subscription media | Finds or watches desirable content | Rights, payment, account | Preview/catalog first vs entitlement-first | Refunds, clarity, access |
| B2B SaaS | Completes one job with trustworthy workspace | SSO, data imports, integrations | Template sandbox vs connect real data | Qualified activation, data accuracy |
| Enterprise/team | First useful shared workflow | Administrator, invitations, roles, approval | Guided provisioning vs invite-first | Access control, deployment success |
| Developer tool/API | First successful request / integration | Credentials, safe sandbox, SDK | Interactive quickstart vs CLI-first | Security, correctness |
| Finance / health | First safe, authorized useful action | Legal identity, compliance, sensitive data | Trust & verification first vs safe demo | Regulation, safety, privacy |
| Hardware / IoT | Device paired and functioning | Firmware, connectivity, Bluetooth | Preflight checklist vs inline pairing | Recovery, reliable connection |
| Public-sector / B2G | Stakeholder validates a credible work result | Procurement, permissions, official review | Guided PoC vs self-service preview | Traceability, accuracy |

## Boundary checks

- Is the user already committed (employee invite, paid purchase) or just evaluating?
- Is the buyer different from the user (student vs parent, employee vs administrator)?
- Can an honest sample communicate value without accessing protected information?
- Would delayed authentication risk data loss or unauthorized disclosure?
- Does value rely on time passing, a scheduled meeting, another party, or an external integration?
- Are multiple flows needed by acquisition source or user sophistication?
- Are there accessibility, localization, mobile bandwidth, or offline requirements?
- What is the *counterexample* to the preferred flow?

**Do not copy the signup or paywall order of a different business model.**

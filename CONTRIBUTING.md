# Contributing

Corrections, new product archetypes, accessibility improvements, and well-sourced research are welcome.

1. Open an issue describing the user problem and proposed change.
2. For empirical claims, cite a primary source and specify the population, comparator, experiment or observation, metric/denominator, date, and limitations.
3. Avoid universal rules, copied conversion lifts, and unsupported benchmarks.
4. Keep the core `SKILL.md` concise; place deeper material under `references/`.
5. Illustrate new patterns with at least one counterexample where the advice would be unsafe or ineffective.
6. Run `python3 scripts/validate_skill.py` before submitting a PR.
7. Never add secrets, private user records, personal DM content, or copyrighted screenshot collections.

This repository provides a research-informed decision process rather than guaranteed growth results.
